    Encoding schemes #

    An encoding scheme serializes the code units of an encoding form as bytes (Unicode Standard, Section 3.10). UTF-16BE and UTF-32BE put the most significant byte of each code unit first, UTF-16LE and UTF-32LE the least significant byte. In these four schemes, a leading U+FEFF is a character like any other. The UTF-16 and UTF-32 schemes start with the byte order mark U+FEFF, which tells the byte order of the rest and is not part of the text. UTF-8 has no byte order, but its data sometimes starts with U+FEFF as a signature.

    A byte sequence whose size is not a multiple of the code unit size is ill-formed: lossy decoding replaces the incomplete code unit at the end with U+FFFD. Lossy UTF-8 decoding replaces each maximal subpart of an ill-formed byte sequence with U+FFFD, following the recommended practice of the Standard, Section 3.9, like UTF8.decodeLossy. Core's String.fromUTF8Lossy replaces each run of ill-formed bytes instead, so it can give fewer U+FFFD.

    decode reports the first ill-formed input with its byte offset, counting the byte order mark or signature.

    detect? finds the scheme of bytes that start with a byte order mark or signature, and name and ofName? convert to and from the IANA charset names of the schemes.

    For streaming, UnicodeFormat.Iterator.EncodingScheme makes each scheme a decoder and an encoder between bytes and characters, with decodeIter and encodeIter.

    Type

    A Unicode encoding scheme.

    • utf8 : EncodingScheme

      UTF-8, where a leading U+FEFF is a character.

    • utf8BOM : EncodingScheme

      UTF-8 with a signature: encoding writes a leading U+FEFF and decoding skips one.

    • utf16BE : EncodingScheme

      UTF-16 in big-endian byte order.

    • utf16LE : EncodingScheme

      UTF-16 in little-endian byte order.

    • utf16 (order : ByteOrder := ByteOrder.big) : EncodingScheme

      UTF-16 with a byte order mark. Encoding writes the mark, then the code units in byte order order. Decoding follows the mark, or reads in byte order order if there is none; the Standard calls for big-endian, the default.

    • utf32BE : EncodingScheme

      UTF-32 in big-endian byte order.

    • utf32LE : EncodingScheme

      UTF-32 in little-endian byte order.

    • utf32 (order : ByteOrder := ByteOrder.big) : EncodingScheme

      UTF-32 with a byte order mark. Encoding writes the mark, then the code units in byte order order. Decoding follows the mark, or reads in byte order order if there is none; the Standard calls for big-endian, the default.

                            def Unicode.EncodingScheme.detect? (b : ByteArray) :
                            Option EncodingScheme

                            The scheme given by the byte order mark or UTF-8 signature at the start of b, if there is one: utf8BOM, utf16 o or utf32 o, so decoding b in that scheme skips the mark. The bytes FF FE 00 00 start both UTF-32LE with a byte order mark and UTF-16LE with a byte order mark followed by U+0000; they are taken as UTF-32LE, as is usual.

                            Only the mark counts: without one, the result is none, even for bytes that are plainly not UTF-8, such as UTF-16 or UTF-32 text without a mark. Callers then choose the scheme, often utf8.

                                def Unicode.EncodingScheme.ofName? (s : String) :

                                The scheme with the IANA charset name or alias s, ignoring ASCII case: UTF-8, UTF-16BE, UTF-16LE, UTF-16, UTF-32BE, UTF-32LE and UTF-32, and their aliases csUTF8, csUTF16BE and so on.
