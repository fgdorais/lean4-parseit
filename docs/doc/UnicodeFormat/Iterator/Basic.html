    Decoding and encoding iterators #

    Decoders and encoders transform pure iterators, Std.Iter over Id, of one kind of token into another: bytes into code units, code units into characters, and back.

    A decoder d : δ with [Decoder δ τ σ] reads one token of type σ from the tokens of type τ at an iterator: Decoder.decode d it continues with the token and the iterator after it, with a DecodeError.Kind and the iterator after the ill-formed input, or with the end of the input. It looks ahead by stepping copies of it, so it needs no buffer. DecodeIterator δ ι repeats it over an iterator of type ι. A strict decoding iterator stops at ill-formed input, where it.decodeError? tells why, it.decodeFailure? finds the first ill-formed input ahead, and it.decodeContinue? goes on after it; a lossy one yields Decoder.replacement d instead and goes on after the ill-formed input. it.decodeFold folds over the tokens and returns the iterator where decoding stopped. DecodeError.Kind and DecodeError have ToString instances for error messages.

    An encoder e : ε with [Encoder ε σ τ] gives the tokens of type τ that encode a token of type σ, and EncodeIterator ε ι yields them for each token of an iterator of type ι.

    Each step of these iterators either moves the inner iterator strictly forward or, for encoders, yields a token that is still pending from the last one. The inner iterator is it.decodeBase or it.encodeBase, and it.encodeBoundary tells whether nothing is pending. Decoders always stop between two tokens, so the position of the inner iterator is the position of the error.
