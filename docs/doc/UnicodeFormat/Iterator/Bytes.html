    Byte order iterators #

    The encoding schemes UTF-16BE, UTF-16LE, UTF-32BE and UTF-32LE serialize code units as bytes. ByteOrder.decodeIter16 reads UTF-16 code units from bytes and ByteOrder.encodeIter16 writes them, and likewise decodeIter32 and encodeIter32 for UTF-32. Bytes that end in the middle of a code unit are ill-formed; lossy decoding replaces that code unit with 0xFFFD, which decodes to U+FFFD.

    To read characters from bytes, EncodingScheme.decodeIter is faster than decoding the code units of these iterators with UTF16.decodeIter or UTF32.decodeIter, about 3.5 times for UTF-16. It reads code units and characters in one layer. Over two layers, the compiler allocates the inner iterator for each character rather than update it in place.

    The UTF-16 and UTF-32 schemes start with a byte order mark: ByteOrder.readBOM16 and readBOM32 read it, and give the byte order it tells and the iterator after it.
